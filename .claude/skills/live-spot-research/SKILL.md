# Live Spot Research

oneul-date 데이터의 신뢰도를 웹 검색으로 보강하는 두 가지 작업 절차.

## A. 기존 스폿 검증 (verify)

스폿 1건당 WebSearch 최대 2~3회. 검색 레시피:

1. `"<스폿명>" <지역> 폐업 OR 영업종료 OR 휴업`
2. `"<스폿명>" <지역> 예약 OR 후기 OR 가격` (최근성 확인)
3. 필요 시 `site:youtube.com "<스폿명>"`

### 판정 규칙
- **open**: 최근 12개월 내 방문 후기/예약/영업 언급 발견
- **closed**: 폐업·영업종료·이전 언급 발견 (출처 URL 필수)
- **unknown**: 위 어느 쪽도 확신 불가 → 필드 수정하지 말 것
- `verified: true`는 open 판정 + 출처 URL이 있을 때만
- 필드 보정(price/location/region/summary)은 출처에서 직접 확인한 값만. 추측 금지.

## B. 트렌드 스폿 조사 (research)

지역 × 슬롯(낮/저녁/밤) 단위 미션. 검색 레시피:

1. `<지역> 데이트 <카테고리> 2026 추천` / `... 요즘 뜨는`
2. `site:youtube.com <지역> <카테고리>` — 먹을텐데, 또간집, 회사랑 등 인기 채널 커버 스폿 우선
3. 결과에서 상호명·위치·특징·가격대 추출. 이미 DB에 있는 이름은 제외.

### 신규 스폿 기준
- 상호명 + 대략적 위치가 특정되어야 함 (동/읍/면 단위 이상)
- 2024년 이후 언급이 있는 곳만 (오래된 리스트글 재탕 배제)
- 출처 URL 필수. 유튜브 출처면 `sourceType: youtube`

## C. 파이프라인 반영 (메인 세션이 수행)

- 검증 결과 → `scripts/overrides.json` (이름 키 패치: 필드 보정, verified, 폐업 시 제외)
- 신규 스폿 → `D:\git\obsidianVault\sources\Live_Research_*.md` 문서 작성
  - 스폿 섹션 필수 필드: `- **위치**:`, `- **슬롯**: 낮|저녁|밤|숙박`, `- **분위기**:`, `- **가격**:`, `- **특징**:`, `- **출처**:`
- `python scripts/build_spots_json.py` 재실행 → 빌드 → 커밋 → main 푸시(자동 배포)
