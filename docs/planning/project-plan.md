> 2026-08-15 기획 확정. 2026-08-16 리서치 기반 기획 검토 반영 (RESEARCH-2026-08.md). 취미 프로젝트, 영리 계획 없음.

> 원칙: **기능 심플 (메뉴·버튼 최소화) / 틀 위주 (디자인은 나중에 갈아입힘) / 모바일 웹 우선**

## 1. 제품 정의

- **중심 기능**: 조건 선택형 **코스 자동 생성기**. 취향은 필터로 반영.
- **데이터**: 인터넷/유튜브에서 데이트 스폿을 조사해 지속적으로 DB화 (Obsidian → 파서 → JSON).
- **수요 흐름**: 조건 선택 → 코스 생성 → 스텝별 교체로 다듬기 → 텍스트 복사해서 카톡 전달.

## 2. 코스 구조

- 코스 = **시간대 슬롯 기반 가변 스텝** (슬롯당 스폿 1개, 1~4스텝)

| 슬롯 | 채우는 스폿 | 비고 |
|---|---|---|
| ☀️ 낮 (day) | 카페 · 전시 · 산책 · 액티비티 | |
| 🌆 저녁 (evening) | 다이닝 · 맛집 | |
| 🌙 밤 (night) | 바 · 야경 · 심야 스폿 | |
| 🏠 숙박 (stay) | 독채 · 풀빌라 · 료칸 | 켜면 1박 코스 (당일/1박 토글 불필요) |

- 내부 표현: **코스 = 스폿 ID 배열** — 저장·복사·링크 공유(URL 해시 인코딩, 3절)가 전부 이 표현에서 파생.
- 생성은 **앵커 기반 근접 자동** — 후보가 가장 귀한 슬롯을 앵커로 먼저 뽑고, 나머지는 같은 시·군·구(area) → 같은 권역 순 폴백.
  > 근거: 시간대별 이동 거리가 코스 품질의 핵심이라는 사용자 테스트 피드백 반영 (2026-08-15)
- **체감 랜덤 보정**: 교체·전체 다시 뽑기 시 최근 등장 스폿 제외(세션 + localStorage 이력), 같은 동네(area)·카테고리 연속 등장 억제.
  > 근거: 통계적 랜덤 ≠ 체감 랜덤 — Spotify 셔플 사례 (2026-08-16, RESEARCH-2026-08.md)

## 3. 화면 구성 (IA)

**단일 화면. 탭·햄버거 메뉴 없음.**

```
[홈 화면]
 ├─ 오늘의 코스: 날짜 시드 고정 코스 1개 자동 노출 (최상단)
 ├─ 조건 영역: 슬롯 토글 4개 + 지역 선택 + 분위기 선택 + [코스 만들기]
 ├─ 결과 영역: 스텝 카드 목록 (카드마다 🔄 교체 버튼 + 네이버 지도 링크)
 ├─ 액션: [🔄 전체 다시 뽑기] [📋 텍스트 복사] [🔗 링크 공유] [💾 코스 저장]
 └─ 상단: [저장한 코스] 버튼 하나
```

### ✨ 오늘의 코스
- 첫 화면 최상단에 **날짜 시드 고정 코스 1개** 자동 노출 — 누구나 같은 날 같은 코스, 서버 불필요
- 그 아래 기존 조건 생성 영역은 그대로 유지
> 근거: 빈 화면 대신 즉시 결과 + Wordle식 재방문 장치 (2026-08-16, RESEARCH-2026-08.md)

### 조건 축 (2축 + 슬롯)
- **지역**: 권역 8종 (서울/경기·인천/강원/충청/영남/호남/제주 + 전체) — **토글식 다중 선택 (합집합)**. '전체'는 개별 선택 전부 해제 시 자동 복귀
  > 근거: 인접 권역을 묶어 찾는 실사용 패턴 반영 (2026-08-15)
- **분위기**: 8종 (로맨틱/힐링/럭셔리/미식/액티비티/뷰·전망/레트로·전통/핫플 + 전체) — **기본 노출 4종(로맨틱/힐링/미식/핫플) + '⋯ 더보기' 탭으로 나머지 4종(럭셔리/액티비티/뷰·전망/레트로·전통)**. 데이터는 8종 유지, UI만 접기
  > 근거: 사전 필터가 무거우면 버튼 누르기 전에 결정 피로 발생 — 원-액션 UX 연구 (2026-08-16, RESEARCH-2026-08.md)
- 예산·실내외 등 추가 축은 데이터가 받쳐줄 때 검토 (백로그)

### 🔄 교체 = 즉시 랜덤
1. 스텝 카드의 🔄 탭 → 해당 슬롯 + 생성 시점 조건(지역·분위기)에 맞는 후보 중에서 **현재 코스에 든 스폿을 제외하고 즉시 랜덤 교체**
2. 그 스텝만 바뀌고 나머지 스텝은 유지
3. 후보 0건이면 토스트로 안내
- [🔄 전체 다시 뽑기]: 동일 조건으로 코스 전체를 재생성
- 교체·전체 다시 뽑기 모두 **체감 랜덤 보정**(2절) 적용
> 근거: v1 사용자 테스트 결과 후보 목록이 너무 많아 선택 불가 → 즉시 랜덤으로 회귀 (2026-08-15)

### 🗺️ 지도 링크
- 각 스텝 카드에 장소별 **네이버 지도** 링크 제공 (1차 네이버 지도 확정)

### 스텝 카드 신뢰 장치
- **한 줄 추천 이유**: 분위기 태그 기반 자동 생성 — 짧게 유지 (길면 역효과)
- **'확인된 장소' 뱃지**: verified 스폿에 표시
> 근거: 사진·리뷰 없는 약점의 최저비용 상쇄 (2026-08-16, RESEARCH-2026-08.md)

### 🔗 링크 공유 (백로그에서 승격)
- 코스(=스폿 ID 배열)를 **URL 해시에 인코딩**한 공유 링크 — 받은 사람이 링크만으로 코스 재현
- 코스 저장(localStorage)과 병행
> 근거: iOS localStorage 임의 삭제 리스크 헤지 + 받은 사람 코스 재현 (2026-08-16, RESEARCH-2026-08.md)

### 저장
- 완성 코스를 통째로 localStorage 저장 (스폿 ID 배열 + 생성 조건 + 저장일)
- 기존 스폿 단위 위시리스트는 **제거**
- [저장한 코스] → 목록 → 탭하면 그 코스를 결과 영역에 복원
- 저장 화면에 **"카톡 복사가 확실한 보관"** 안내 병기
  > 근거: iOS가 미사용 시 localStorage를 임의 삭제 — 지킬 수 없는 약속을 하지 않기 (2026-08-16, RESEARCH-2026-08.md)

### 텍스트 복사 포맷 (v2)
카톡에 붙였을 때 그대로 예쁜 **정형 포맷**으로 고급화:

　양평 강하면 — 한 줄 추천 이유

🏠 숙박 · 독채 C

> 근거: Wordle 이모지 그리드 — 텍스트도 포맷이 정형·예쁘면 퍼진다 (2026-08-16, RESEARCH-2026-08.md)

## 4. 데이터

### 스폿 스키마 v2 (목표)
```jsonc
{
  "id": 1,
  "name": "스폿명",
  "slot": "day | evening | night | stay",   // ★ 신규, 생성기 필수
  "region": "서울 | 경기 | ...",
  "mood": ["romantic", "healing", ...],      // 분위기 매칭용, 8종: romantic|healing|luxury|foodie|active|view|retro|trendy (현 키워드 검색 → 필드화)
  "location": "양평 서종면 ...",
  "area": "성동구 | 수원시 | null",          // ★ 신규, 시·군·구, 근접 매칭용 — location에서 파서가 추출
  "price": "…",                              // 없으면 null
  "summary": "킬링 포인트 한 줄",
  "source": { "type": "youtube|web|manual", "url": null, "note": "" },  // ★ 신규
  "verified": false                          // ★ 신규, 내가 확인한 곳 표시
}
```

### 재가공 전략
- **휴리스틱 자동 분류로 시작** — 파서(`build_spots_json.py`)에 키워드 규칙 추가해 3,171건 전량에 slot 부여. 비용 제로, 부정확한 건 쓰면서 교정.
- **분위기 8종 키워드 휴리스틱 확장** — 기존 4종(romantic/healing/luxury/foodie) 키워드 규칙에 active/view/retro/trendy 4종 규칙을 추가해 mood 필드 부여
- slot 판정 불가 건은 `slot: null` → 생성기 후보에서 제외 (틀린 슬롯에 넣는 것보다 안전)
- 신규 조사 워크플로우: 인터넷/유튜브 조사 → Obsidian 문서 작성 → 파서 재실행 → JSON 갱신
- **라이브 검증 절차**: `.claude/skills/live-spot-research` 스킬로 웹/유튜브 검색 기반 스폿 검증(폐업/영업 확인, verified 부여) 및 트렌드 신규 스폿 조사를 수행. 결과는 `scripts/overrides.json`(이름 키 패치)과 Obsidian 신규 문서로 반영.

### 확충 우선순위
- **밤(night) 슬롯**: 바 위주 → **무알코올 심야 스폿**(야간개장 전시·야경 산책·심야 카페) 위주로 보강
- **낮(day) 슬롯**: 팝업스토어·러닝 코스·근교 반나절 스폿 보강
- **price 필드 채우기**: 커플 83%가 데이트 비용으로 갈등 — 예산 필터(백로그)의 전제
> 근거: 무알코올 재편·팝업 연 3,000개·비용 갈등 통계 (2026-08-16, RESEARCH-2026-08.md)

## 5. 틀 위주 설계 원칙 (구현 시 준수)

- **디자인: A안 감성 매거진 확정 (2026-08-15), 상세는 docs/DESIGN.md**

1. **디자인 토큰 분리**: 색·간격·폰트는 전부 CSS 변수. 마크업은 시맨틱 클래스만 → 나중에 스킨 교체 = CSS 파일 교체
2. **렌더/로직/데이터 분리**: 생성 로직(순수 함수) ↔ 렌더 함수 ↔ 상태. 프레임워크 없이 유지하되 교체 가능한 경계 유지
3. **코스 = ID 배열**: 저장·복사·공유 모두 이 표현 위에서 파생
4. **코스 공유는 URL 해시 인코딩 확정**(3절 링크 공유) — 그 외 상태의 URL화는 보류하되 구조상 막지 않기

## 7. 하지 않을 것 (연구 근거로 기각 — 재론 방지)

- **UGC·커뮤니티·리뷰 기능** — 신뢰는 이미 네이버 리뷰(57%)에 있음. 콜드스타트만 안게 됨
- **틴더식 스와이프** — 결정 피로 재생산. 현 구조(결과 먼저 + 교체)가 우수
- **채팅형 AI 인터페이스** — 장소 최종 결정에서 AI 비중 3%. 카카오맵 AI와 정면 대결 회피
- **술·바 카테고리 확대** — 무알코올 재편 트렌드. 무알코올 저녁·심야 데이터 확충이 우선 (4절)
- **계정·서버·앱 설치** — "설치·로그인·서버 없이 열자마자 코스"라는 가벼움이 포지셔닝 그 자체
> 근거: 기각 사유 상세는 리서치 5절 참조 (2026-08-16, RESEARCH-2026-08.md)

## 8. 백로그 (지금 안 함)

- 네이버 장소ID 딥링크 (검색 링크 → 정확 장소 연결)
  > 근거: 이동의 62%가 네이버지도 — 링크 정확도가 곧 제품 신뢰 (2026-08-16, RESEARCH-2026-08.md)
